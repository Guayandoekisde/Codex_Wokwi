# Actividad de GitHub Classroom: Propuesta de Práctica Temática Pequeña

## Descripción general
En esta actividad vas a diseñar una **propuesta de práctica temática pequeña** enfocada en resolver una necesidad concreta con herramientas de bajo costo técnico: **ARM64 Assembly, C, Python o Bash**.

La prioridad es que primero construyas una propuesta bien documentada y viable para un proyecto corto, claro y ejecutable en entorno local sin dependencias complejas.

## Objetivo de aprendizaje
Al finalizar esta actividad serás capaz de:

- Definir un problema técnico pequeño y acotado.
- Justificar la elección de un lenguaje de programación según el contexto.
- Diseñar la estructura base de un repositorio profesional.
- Documentar caso de uso, alcance y pruebas mínimas.
- (Opcional) Implementar un prototipo funcional mínimo.

## Lenguajes permitidos
- ARM64 Assembly
- C
- Python
- Bash

## Reglas para mantener el proyecto pequeño
1. El problema debe resolverse con alcance mínimo funcional.
2. Evita arquitectura compleja y división excesiva de módulos.
3. No uses frameworks.
4. No uses bases de datos.
5. No uses Docker o contenedores.
6. No uses APIs externas ni servicios en la nube.
7. No agregues dependencias difíciles de instalar.
8. Si eliges ARM64 Assembly, limita la práctica a programas muy pequeños.

## Entregables esperados
1. `docs/propuesta.md` completo.
2. `docs/caso_de_uso.md` completo.
3. `docs/estructura_repositorio.md` revisado y adaptado al proyecto.
4. `docs/plan_de_pruebas.md` con casos de prueba mínimos.
5. `tests/test_plan.md` marcado como checklist final.
6. (Opcional) Prototipo mínimo en `src/main.<ext>`.
7. Script de ejecución adaptado en `scripts/run.sh`.

## Instrucciones para el estudiante
1. Lee este `README.md` completo.
2. Elige **un solo lenguaje principal**.
3. Llena `docs/propuesta.md` antes de programar.
4. Llena `docs/caso_de_uso.md` con un escenario real y pequeño.
5. Revisa `docs/estructura_repositorio.md` y ajusta nombres solo si es necesario.
6. Define tus pruebas en `docs/plan_de_pruebas.md`.
7. Completa el checklist de `tests/test_plan.md`.
8. Si te alcanza el tiempo, implementa un prototipo mínimo.

## Criterios generales de evaluación
- Claridad del problema y objetivo.
- Coherencia entre lenguaje elegido y solución propuesta.
- Alcance pequeño, realista y bien delimitado.
- Calidad y orden de la documentación.
- Estructura del repositorio limpia y consistente.
- Calidad de pruebas mínimas documentadas.
- (Opcional) Funcionamiento básico del prototipo.

## Ejemplos de temas posibles
- **Mini Toolkit en ARM64**
- **Asistente de Estudio en Terminal**
- **Reporteador de Información del Sistema**
- **Organizador de Archivos**
- **Juego de Aprendizaje en Línea de Comandos**

## Nota importante
En esta actividad **primero se documenta y justifica la idea**. Después, de manera opcional, se implementa un prototipo pequeño. La calificación prioriza la planeación y documentación técnica sobre la cantidad de código.
